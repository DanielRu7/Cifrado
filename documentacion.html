Cómo funciona César & Atbash

Ver programa

1. Alfabeto parametrizable

El sistema no trabaja con un alfabeto fijo de 26 letras: trabaja con un arreglo ordenado de caracteres que el usuario define libremente en el campo "Alfabeto". Por default se carga el conjunto completo de caracteres imprimibles de ASCII (códigos 32 al 126, 95 símbolos en total), pero puede reemplazarse por cualquier otro conjunto: solo minúsculas, minúsculas con ñ, alfabetos con dígitos, alfabetos con mayúsculas, etc.

La posición de cada carácter dentro de ese arreglo es lo único que le importa al algoritmo. César y Atbash no cifran "letras": cifran índices dentro del alfabeto que se les dio.

2. Cifrado César

Cada carácter del texto se busca dentro del alfabeto activo, se toma su índice, se le suma (o resta, para descifrar) un desplazamiento k, y el resultado se envuelve con módulo para no salirse del arreglo: 

cifrado(c)    = alfabeto[ (indice(c) + k) mod n ]
descifrado(c) = alfabeto[ (indice(c) - k) mod n ]

Donde n es el tamaño del alfabeto activo. Si el usuario cambia el alfabeto, automáticamente cambia también el "universo" de desplazamientos posibles (n - 1 desplazamientos válidos).

3. Cifrado Atbash

Atbash invierte el orden del alfabeto: el primer carácter se intercambia con el último, el segundo con el penúltimo, y así sucesivamente. Es involutivo: aplicar Atbash dos veces regresa el texto original, por eso la misma función sirve para cifrar y para descifrar. 

atbash(c) = alfabeto[ n - 1 - indice(c) ]

4. Limpieza de ruido

Antes de intentar descifrar nada, el sistema recorre el texto cifrado y elimina por completo (no salta, no deja parado) cualquier carácter que no pertenezca al alfabeto activo. Esto incluye símbolos decorativos, emojis, caracteres de otros idiomas, y también caracteres invisibles que suelen usarse para "esconder" ruido al copiar y pegar (espacios de ancho cero, marcas de dirección de texto RTL/LTR, BOM). El objetivo es que ese ruido no contamine el análisis de frecuencias ni aparezca mezclado en el resultado final.

5. Criptoanálisis automático (Al-Kindi)

Al descifrar, el sistema nunca le pregunta al usuario qué método o qué desplazamiento usar. En vez de eso, genera todos los candidatos posibles: 1 candidato Atbash más n - 1 candidatos César (uno por cada desplazamiento posible dentro del alfabeto activo), y evalúa cada uno con una prueba de bondad de ajuste chi-cuadrada contra las frecuencias conocidas de las letras en español — la técnica de análisis de frecuencias que se le atribuye a Al-Kindi, considerado el primer criptoanalista de la historia.

El candidato con menor chi-cuadrado es el único que se muestra. El factor humano no interviene en la decisión.

Detalle importante de fiabilidad estadística: un chi-cuadrado sin ajustar es engañoso cuando los candidatos tienen tamaños de muestra muy distintos, porque una muestra pequeña de letras puede "coincidir" con las frecuencias esperadas por pura casualidad. Para evitar falsos positivos, el sistema:

  • Descalifica cualquier candidato cuya cantidad de letras reconocidas sea menor a un mínimo razonable.
  • Normaliza el chi-cuadrado dividiendo entre el total de letras contadas (chi-cuadrado reducido), para que muestras grandes y chicas sean comparables entre sí.
  • Si ni siquiera el mejor candidato alcanza el mínimo de muestra, el sistema avisa explícitamente que el texto es demasiado corto para una detección confiable, en vez de inventar una respuesta.
